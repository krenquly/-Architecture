# ADR-001. Управление приоритетами каскада

**Статус:** принято · **Дата:** 18.11.2026

## Контекст

Две команды пишут CSS: Atlas UI (components/states) и подрядчик (legacy.css). В DevTools видны два конфликта: кнопка primary в `#workbench` (unlayered `#id .class` бьёт слой components) и danger-метка (глобальный `.is-danger` из states бьёт `.ui-tag--danger`).

## Рассмотренные варианты

| Альтернатива | Плюсы | Риски | Почему выбрали или отклонили |
|---|---|---|---|
| A. Всё в одном CSS-файле | Просто | Нет изоляции, конфликты | Отклонено |
| B. БЭМ + регламент | Понятный нейминг | Не решает unlayered legacy и `!important` | Используем как нейминг, но не как единственное решение |
| C. @layer + токены + контракт | Изоляция, предсказуемость, управление `!important` | Требует дисциплины | **Выбрано** |
| D. Только CSS Modules | Локальность | Общие токены/слои остаются общей системой; vendor CSS не решает | Отклонено как единственное |

## Решение

- **Порядок слоёв:** `@layer reset, legacy, tokens, base, components, states, utilities;`
- **Принцип специфичности:** максимум 0-1-0 для компонентов; ID запрещены; `:where()` для reset; `:is()` без ID.
- **Публичные классы и модификаторы:** `.ui-button`, `.ui-button--primary|secondary|ghost|danger`, `.ui-button--sm|lg`; `.ui-tag--neutral|success|warning|danger`; `.ui-alert--info|success|warning|danger`.
- **Зависимость от селекторов родителя:** запрещена; компонент оформляет только свои прямые элементы и слоты (`__*`).
- **Third-party CSS:** `@import url('./legacy.css') layer(legacy);` + scope `.legacy-widget`.

## Последствия и риски

При подключении новой библиотеки её CSS импортируется в `layer(vendor)` перед `components`. Регрессию ловим через `npm test` (18 проверок) и E2E. Риск: `!important` в vendor — его нужно переписывать, слой сам не спасает.

## Два контрпримера

1. **Почему `!important` не решение?** Он переворачивает порядок слоёв (ранний слой сильнее), делает отладку невозможной и не устраняет архитектурную причину.
2. **Где одного `@layer` недостаточно?** Если внутри слоя есть ID-селектор или `!important`, он может перебить другие слои; нужна дисциплина селекторов и явное ограничение scope.
